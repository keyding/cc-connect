# Domain Docs

## 布局与读取

采用单领域结构：

- CONTEXT.md：仓库根目录的领域术语表。
- docs/adr/：有必要记录的架构决策。

探索代码前读取 CONTEXT.md，并读取涉及当前主题的 ADR。
文件尚不存在时继续工作，由 domain-modeling 在术语或决定
形成时按需创建。

## 使用规则

- 需求、Issue 标题、测试名称和设计讨论使用术语表中的名称。
- CONTEXT.md 只保存领域定义；规格、实现方案和工作进度
  放在相应文档或 Issue。
- 现有术语表标明的目标含义，不等于功能已实现。
- 发现术语缺口时交由 domain-modeling 澄清。
- 方案与既有 ADR 冲突时，明确指出冲突和重新讨论的理由。
