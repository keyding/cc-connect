# 共享会话目录与持久任务

共享目录允许授权成员跨 Topic 创建、发现和选择固定 Agent 的会话。任务持久接收，保留提交目标并按会话及实际目录串行执行。完整真实联合验收仍待执行，见 [Spec #13 验证记录](validation/spec-13.md)。

## 全新实例与配置

试用实例使用独立配置、独立 Bot Token 和全新的绝对 `data_dir`，保留旧实例状态、Agent 历史、代码和 worktree，不复制旧状态或自动迁移。参考 [配置示例](../config.example.toml)：

```toml
# 配置顶层
language = "zh"
data_dir = "/absolute/path/to/cc-connect-directory-preview"

# 在已有项目的 Telegram [projects.platforms.options] 下添加：
# shared_session_directory = true
# share_session_in_channel = false
# allow_from = "<A 的 Telegram 数字 ID>,<B 的 Telegram 数字 ID>"
```

`shared_session_directory` 默认 false；启用后仅群和超级群使用共享目录，私聊及其他平台保持既有行为。群消息仍遵循 @Bot / `group_reply_all` 设置。重启继续使用相同 `data_dir`、项目名称和选择模式。目录不导入 Agent 历史，新建会话不创建分支或 worktree；新状态也不等于隔离 Agent 登录账号和操作系统环境。

Claude Code 使用已配置的本地 CLI。Codex 默认 `backend="exec"` 没有交互审批 IPC，即使 `mode="suggest"` 也不会弹出在线审批；需要交互审批时在 Codex agent options 设置 `backend="app_server"`，使用本地 app-server。CLI 登录及真实服务验证需另外完成。

## 会话、选择与回复

| 命令 | 行为 |
| --- | --- |
| `/new [名称]` | 创建并选择会话；无名生成唯一名称，重名不会自动加入。 |
| `/list` | 列出同项目同群跨 Topic 的会话，显示名称、固定 Agent、稳定 ID 和当前选择。 |
| `/switch <序号、完整名称或稳定 ID>` | 改变本入口默认；数字优先解释为序号。 |
| `/name <新名称>` 或 `/rename <新名称>` | 改名当前会话；首尾空白、ASCII 大小写不构成区别。 |
| `/current` | 查看当前选择。未选择时先创建/选择，原消息不会留待自动执行。 |
| `/history [条数]` | 查看当前共享会话最近的已完成对话，默认 10 条消息；跨用户、跨 Topic 及重启后可用。只读取本实例保存的请求和结果，不导入 Agent 账号旧历史。 |
| `/help` | 查看当前共享模式支持的命令和说明，与 Bot 菜单使用同一清单。 |

`share_session_in_channel=false` 时每人每 Topic 独立选择；true 时同 Topic 的授权成员共用默认。无 Topic 时使用群入口。目录不跨群、项目或平台共享。

引用已登记的 Bot 文本、媒体、分段或进度回复会投向原会话，不改变默认选择。跨 Topic 必须有可靠的协议来源信息；转发文本、用户引用、未知或失效关联不能猜测会话。关联没有按天过期，但无法补录旧实例或丢失的回执。删除后的旧引用失效。投递部分失败只保留已确认成功的关联，不重新执行任务，也不改投其他位置。

## 队列与恢复

| 命令 | 行为 |
| --- | --- |
| `/queue [会话 ID]` | 查看请求 ID、发起人和状态；省略时使用当前会话。 |
| `/cancel [请求 ID]` | 仅发起人可取消未开始请求；省略时选择自己当前会话中的排队请求。 |
| `/stop [请求 ID]` | 任一当前授权成员可停止运行任务；等待执行者退出，保留后续队列。 |
| `/resume <请求 ID>` | 退出已确认后显式恢复未开始的任务，不重放已开始请求。 |
| `/resolve [请求 ID]` | 处理已确认执行者退出的中断任务，保留已有结果；后续队列仍需显式恢复。 |
| `/continue [请求 ID]` | 发起人先查看可能已执行工具的警告；按提示确认。当前无法恢复工具进度时明确提示不支持，不发送原任务重试。 |

请求、附件及固定会话、Agent、发起人、回复位置在接收时保存，之后改名或切换不会改投。成功写盘后才确认接收；若最终提交状态不确定，返回稳定请求 ID 与查询提示并阻止执行，不算接收成功。用 `/queue <会话 ID>` 核对后再决定是否重新提交，避免重复。

同一进程内，相同实际项目目录的共享任务互斥（含符号链接），无冲突目录可并行。此约束不隔离其他进程、旧非共享入口或 Agent 自行跨目录写入。音频按原始文件保存，不在接收前转录。

开始执行前保存检查点；可靠完成、确认执行者退出且结束状态落盘后才放行。失败、中断和不确定记录暂停相关工作。重启只恢复确定未开始的请求；可能已执行过的任务不自动重放。接收未提交不能冒充成功，结束未提交不能冒充完成。

本地受支持执行路径记录进程组身份；子进程仍存活时不能仅凭父进程退出解锁。进程启动到身份持久化之间的窗口、远端或无法证明退出的后端保持保守阻塞。脱离进程组的写入不在退出证明范围内。历史续聊不是工具进度恢复；不要把 `/continue` 当作安全重试。结果投递失败也不重跑 Agent。

## 审批、撤权与删除

审批和提问使用消息生成的按钮或 `/approve <token>`、`/deny <token>`、`/answer <token> <题号> <答案或选项序号>`。仅原请求发起人且仍有权限者可操作，令牌绑定具体请求/问题。普通回复审批文本不算新任务或批准；重复、过期、重启前及已停止任务的按钮失效。审批消息显示请求操作供判断。

等待交互期间保留目录锁与队列，不默认批准。既有最大执行时间继续适用，等待时暂停事件空闲计时；Codex app-server 保留既有五分钟交互等待超时，超时中断并暂停任务。未新增跨 Agent 的全局审批超时。

配置 `allow_from` 变更通过配置重载生效，每次共享操作检查当前权限，并核对排队/运行请求的发起人。撤权取消该人的未开始任务、停止其运行/等待任务并使交互失效，其他成员和历史保留。这里是配置授权撤销，不是轮询 Telegram 群成员身份。

`/delete [会话 ID]` 只允许删除无待处理请求的会话；按返回的 `/delete <token> confirm` 再确认，token 不是会话 ID。新增任务会使旧确认失效。删除移除目录、默认选择与消息关联，保留代码、worktree、Agent 历史及已保留的任务材料；不以此清理旧数据。

自动化包含真实文件重建、可控 CLI 子进程、Telegram HTTP 契约和故障注入。它们不代替两个真实账号、两个 Topic、两种选择模式及两个真实 Agent 的联合验收，也不授权切换现有服务。

## 显示与命令菜单

`/list` 在当前选择的条目前显示 `👉`，序号及 `/switch` 的对应关系不变。
启用共享目录后，Bot 菜单公布共享模式已接入的命令；`/help` 同时说明参数和别名。恢复、审批、历史等命令均提供五种语言说明，项目禁用的命令不在菜单中显示。未接入共享模式的旧命令不会因菜单展示而获得执行权限。

```toml
[display]
tool_messages = false                 # 隐藏工具进度提示
shared_acceptance_messages = false    # 隐藏无需等待时的成功接收提示
```

`shared_acceptance_messages` 默认 `true`，可在 `[projects.display]` 覆盖。设为 `false` 不改变先保存再执行的规则；同会话有前序任务或队列暂停时仍提示排队/暂停，接收失败、状态不确定和审批提示始终保留。此开关与 `instant_reply` 独立。
